# 完整项目方案

## 1. 项目目标

开发一台家用远程鱼食投喂器：鱼缸附近有 2.4GHz Wi-Fi，用户在户外通过手机浏览器打开自己的控制页面，查看设备在线状态并手动投喂。第一版不包含视频，也不要求原生接入米家。

设计约束：

- 不购买云服务器，不支付固定月费。
- 不使用 MixIO 自带的项目界面。
- 使用现有 ESP8266 Wi-Fi 开发板。
- 使用简单、易接线的舵机机构。
- 网络异常、重复消息和设备重启不能造成明显的重复投喂风险。

## 2. 最终技术路线

| 层级 | 选型 | 职责 |
|---|---|---|
| 手机界面 | 原生 HTML/CSS/JavaScript | 自定义控制、状态、历史和连接设置 |
| 静态托管 | GitHub Pages + Actions | 提供 HTTPS 页面，不运行后端函数 |
| 消息平台 | MixIO 免费主站 | MQTT 消息转发和在线连接 |
| 浏览器通信 | MQTT.js + WSS 8084 | 加密连接 MixIO，发布命令、订阅状态 |
| 设备通信 | PubSubClient + MQTT 1883 | ESP8266 接收命令、发布确认和状态 |
| 命令认证 | HMAC-SHA256 | 防止只有 MixIO 项目密码的人伪造投喂命令 |
| 执行机构 | MG90S 180°舵机 | 驱动旋转量杯或翻转料杯 |
| 状态保存 | ESP8266 EEPROM | 保存防重放和投喂限额状态 |

不再使用 Supabase、GitHub API、数据库和定时轮询。GitHub Actions 只负责发布静态文件；手机页面和设备都主动连接 MixIO，命令延迟通常由 MQTT 网络决定。

## 3. 数据流

```text
1. 手机网页连接 wss://mixio.mixly.cn:8084
2. ESP8266 连接 mixio.mixly.cn:1883
3. 双方订阅同一账号和项目下的主题
4. 手机生成 UUID 和 45 秒有效期
5. 手机使用共享密钥计算 HMAC-SHA256
6. ESP8266 校验签名、时间、重复编号和投喂限额
7. ESP8266 先写 EEPROM，再驱动舵机
8. ESP8266 发布 processing/completed/rejected 状态
9. 手机更新页面和本地历史记录
```

## 4. MQTT 主题

主题完整形式为 `MixIO用户名/项目名/主题名`。

| 主题名 | 方向 | 说明 |
|---|---|---|
| `feeder_cmd` | 手机 → 设备 | 带签名的投喂命令 |
| `feeder_ack` | 设备 → 手机 | 接收、完成或拒绝结果 |
| `feeder_state` | 设备 → 手机 | 遥测和安全状态，保留消息 |
| `feeder_online` | 设备 → 手机 | 在线状态和 MQTT 遗嘱，保留消息 |
| `feeder_query` | 手机 → 设备 | 请求立即上报状态 |

## 5. 设备状态机

```text
启动
 ├─ 初始化 EEPROM
 ├─ 舵机回到关闭角度
 ├─ 连接 Wi-Fi、同步 NTP
 └─ 连接 MixIO、订阅命令
           ↓
        等待命令
           ↓
    格式与签名校验
      ├─ 不通过 → rejected
      └─ 通过
           ↓
   时效/重复/限额校验
      ├─ 不通过 → rejected
      └─ 通过
           ↓
       EEPROM 预提交
           ↓
       processing 确认
           ↓
        舵机动作
      ├─ 完成 → completed
      └─ 异常 → failed
```

EEPROM 预提交是关键安全措施。如果舵机动作期间突然断电，设备重启后仍记得该命令已经被领取，不会再次执行同一个 MQTT 消息。

## 6. 机械方案

推荐使用“旋转量杯”，而不是仅按时间打开粮仓闸门：

- 关闭位置：量杯对准粮仓，装入一份鱼粮。
- 打开位置：舵机转动约 70～100°，量杯对准鱼缸并倒出。
- 回位：量杯返回粮仓，等待下一次投喂。
- 多份投喂：重复完整的打开—关闭循环。

这种结构的份量主要由量杯容积决定，受舵机速度和鱼粮流速影响较小。颗粒鱼粮最适合；薄片鱼粮需要更大的开口和防架桥设计。

## 7. 安全边界

本方案同时使用两类凭据：

1. MixIO 项目密码：允许连接项目并收发消息。
2. 命令签名密钥：只保存在手机浏览器和 ESP8266 固件中，用于证明命令来自你的页面。

即使 MixIO 项目密码在未加密的 1883 链路上被观察到，没有命令签名密钥也无法生成新的有效投喂命令。命令还必须在 45 秒内到达，重复 UUID 会被 EEPROM 拒绝。

仍然存在的风险：攻击者可能伪造设备状态、干扰 MQTT 连接或阻断网络。家庭自用第一版通常可以接受；商业产品不应使用这个安全等级。

## 8. 开发阶段

### 阶段 A：电气台架

- ESP8266 单独烧录，确认 Wi-Fi 和 MixIO 在线。
- 舵机独立 5V 供电，共地连接。
- 不安装鱼粮，校准关闭和打开角度。

### 阶段 B：机械样机

- 制作旋转量杯和粮仓。
- 测量每个循环的平均克数和误差。
- 连续运行至少 100 次，检查卡料、回位和舵机发热。

### 阶段 C：远程联调

- GitHub Pages 部署自定义网页。
- 使用手机流量测试远程投喂。
- 测试 Wi-Fi 中断、MQTT 重连、重复消息和命令过期。

### 阶段 D：长期运行

- 连续上电 7 天。
- 测试停电恢复、路由器重启和 MixIO 短时不可用。
- 加装防潮外壳、线缆固定和机械限位。

## 9. 后续扩展

- 增加光电落料检测，区分“舵机完成”和“实际落粮”。
- 增加称重传感器，显示粮仓余量。
- 增加 DS18B20 水温传感器。
- 增加本地定时投喂，断网仍可执行固定计划。
- 使用 Home Assistant 或 Matter 做家庭自动化桥接。
- 商业化时更换为 TLS MQTT、设备独立证书和正式 MIoT/Matter 认证。

# MixIO 注册、项目和主题配置

## 1. 使用主站账号项目

打开 [MixIO 主站](https://mixio.mixly.cn) 注册并登录。创建一个普通账号项目，例如：

```text
项目名称：fish-feeder
```

不要使用以 `@` 开头的 Mixly Key 公开项目。公开项目只要知道工程名就可能访问或发布主题，不适合远程投喂器。

## 2. 记录三项信息

进入项目后记录：

1. MixIO 用户名。
2. 项目名称。
3. 项目密码。

项目密码用于 MQTT 设备连接，不是账号网页登录密码。网页和 ESP8266 都需要使用同一组用户名、项目名称和项目密码。

不要把账号登录密码、项目密码或命令签名密钥提交到公开 GitHub 仓库。

## 3. 不需要设计 MixIO 页面

本项目不使用 MixIO 自带的按钮、图表和布局。MixIO 只承担 MQTT Broker：

- 自定义网页从 GitHub Pages 加载。
- 网页连接 `wss://mixio.mixly.cn:8084`。
- ESP8266 连接 `mixio.mixly.cn:1883`。
- 双方使用 MQTT 主题直接通信。

因此 MixIO 项目可以保持空白，不需要添加任何组件。

## 4. 本项目主题

假设用户名为 `myname`，项目名为 `fish-feeder`，完整主题如下：

```text
myname/fish-feeder/feeder_cmd
myname/fish-feeder/feeder_ack
myname/fish-feeder/feeder_state
myname/fish-feeder/feeder_online
myname/fish-feeder/feeder_query
```

固件和网页会自动拼接主题，不需要在 MixIO 后台手工创建。

## 5. 创建命令签名密钥

自定义网页第一次打开时会显示连接设置：

1. 填写 MixIO 用户名。
2. 填写项目名。
3. 填写项目密码。
4. 点击“生成”创建 48 位十六进制签名密钥。
5. 点击“复制”。
6. 把它写入 ESP8266 `config.h` 的 `COMMAND_SECRET`。

示例：

```cpp
#define COMMAND_SECRET "8d2f...此处应为你自己生成的随机值...2a19"
```

网页和固件必须完全一致，包括大小写。这个密钥不会发送给 MixIO；网页只发送命令和 HMAC 签名。

## 6. 免费层消息频率

MixIO 官方开源配置的默认限制包括每用户每秒最多 5 条消息、最多 20 个项目和最多 1000 条离线存储消息。主站生产配置可能调整，以实际服务为准。

本项目正常流量很低：

- 设备每 60 秒发布一次状态。
- 手机只在打开页面时订阅消息。
- 每次投喂产生一条命令和约两条确认。

这远低于教育项目常用的消息频率。不要把状态上报周期设置成 1 秒以内。

## 7. 连接端口与安全性

| 客户端 | 地址 | 加密 |
|---|---|---|
| 自定义网页 | `wss://mixio.mixly.cn:8084` | 是 |
| ESP8266 PubSubClient | `mixio.mixly.cn:1883` | 否 |

ESP8266 端使用 1883 时，MixIO 项目凭据和状态消息不具备传输保密性。项目通过额外 HMAC 签名确保投喂命令不能被随意伪造，但商业产品或高安全场景应更换为 TLS MQTT 或私有安全 Broker。

## 8. 常见问题

### 网页显示 MixIO 连接失败

- 检查项目密码，不是账号登录密码。
- 检查用户名和项目名是否区分大小写。
- 确认手机网络没有封锁 8084 WebSocket 端口。
- 尝试在家庭 Wi-Fi 和手机流量之间切换测试。

### 网页连接成功但设备离线

- 检查 ESP8266 是否连接 2.4GHz Wi-Fi。
- 查看串口中的 MQTT 状态码。
- 确认固件中的用户名、项目名和项目密码与网页一致。
- 确认 `DEVICE_ID` 只用于显示，不影响主题拼接。

### 能看到状态但命令被拒绝

- 网页和固件的 `COMMAND_SECRET` 不一致。
- ESP8266 尚未完成 NTP 时间同步。
- 距上次投喂不足安全间隔。
- 24 小时份量达到上限。
